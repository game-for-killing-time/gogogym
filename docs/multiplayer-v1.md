# 多人連線 v1

更新日期：2026-11-04。此版讓最多12名同時在線玩家進入同一間健身室，互相看見移動、五類訓練姿勢、暫停與表情。原有場景內操作及個人訓練循環保留。Sites 第1版已發布；本機雙瀏覽器、手機佈局及公開網站的雙用戶端同步均已驗證。

公開網址：[Pixel Gym · 街角健身室](https://pixel-gym-club.magicforeveryone2026.chatgpt.site)。發布來源提交：`6ba0620fc1e6549185a377a29acb5e4f8f221b43`。

## 開房與加入

1. 開啟同一個遊戲網址，按右下「房間」或右上開房入口。
2. 輸入1至16字暱稱，按「開新房間」。
3. 按「複製邀請連結」並傳給朋友。
4. 朋友開啟連結，輸入自己的暱稱後加入；亦可在同一網站輸入6位房間碼。
5. 關閉房間面板即可行走或從課表選訓練。房間面板顯示同房名單，亦可主動離開。

沒有加入房間時仍可自行訓練。本機 `127.0.0.1` 網址只供本機預覽；跨地域玩家必須使用同一個已發布的網上網址。不同網址各有獨立的個人訓練存檔。

## 本版的房間規則

| 項目 | 行為 |
| --- | --- |
| 人數 | 最多12名同時在線；伺服器拒絕第13人，離場後可補入 |
| 身分 | 暱稱與每分頁的連線憑證；尚無帳戶或12名固定會員制度 |
| 房間碼 | 6位英文字母／數字，建立後24小時到期 |
| 離線 | 20秒沒有狀態同步即不再佔在線名額，器材亦可由其他玩家使用 |
| 重連 | 使用原憑證回到原身分；逾時後須重新取得名額，滿房會被拒絕 |
| 器材 | 六件現有設施各限一人同時使用；正式與練習均需取得位置 |
| 表情 | 同房可見，約3秒消失；相同封包不會讓表情無限延長 |
| 角色 | 所有人暫用 C01 動畫，配合暱稱和彩色名牌辨認 |

器材使用權由伺服器以單次條件寫入決定。兩人同時選同一件器材時，只會有一人成功；另一人可選其他設施。結束或離開訓練會釋放位置。此安排先驗證共享場景，原構思的熱門器材並行位置留待擴充。

短暫斷線會重試連線，仍有效的身分不會重新建立另一名玩家。逾時後恢復的玩家會清除原器材使用權，避免與已接手的玩家重疊。房間到期後需建立新房；個人訓練存檔不受房間到期影響。

## 同步範圍與限制

共享資料包括玩家位置、面向、是否移動、訓練器材、動作階段、動作幅度、暫停狀態和表情。畫面使用插值減少位置跳動；這些是真實連線玩家，不是模擬在線角色。

能力、熟練次數、每日訓練券、結算分數及天台建設貢獻仍由各自瀏覽器儲存與計算。房間資料庫沒有帳戶進度，不能跨裝置恢復成長，也尚未由伺服器驗證訓練收益。現有每日限額是遊戲原型規則，不能當成正式防作弊機制。

雙人拍檔、團體課、聊天室、固定會員、好友帳戶及完整12人造型動畫尚未加入。多人角色可互相穿過，家具碰撞仍保留。天台顯示的是個人紀錄，並未合併成整房工程進度。

## 連線與部署

`src/multiplayer.mjs` 約每250毫秒提交狀態並取得同房快照；下一次請求會等待上次完成，失敗後退避重試。同步次序防止舊狀態覆蓋新狀態，加入、同步和器材請求依次處理。連線憑證保存在分頁的 sessionStorage，放在請求內容內，不放進分享網址；伺服器快照亦不包含憑證。

`multiplayer-server/handler.mjs` 是本機與網上版本共用的 HTTP 處理程式，驗證房間、憑證、位置、動作數值及器材類別。容量與器材位置由資料庫處理並行競爭。各房資料隔離；伺服器儲存憑證雜湊。

本機執行 `npm start` 使用 Node.js 22.18 以上的內建 SQLite。預設記憶體資料庫會隨本機伺服器重啟清空房間；瀏覽器的個人訓練存檔保留。預設位址為 `127.0.0.1:4178`，可用 `HOST`、`PORT` 調整監聽位址。

`online/` 是 Sites 網上部署專案，使用 D1 保存房間。遊戲前端與共用房間處理程式由主專案複製進部署專案；修改後須同步副本，再進行建置及發布。D1 表結構與本機的 `migrations/0001_multiplayer.sql` 相同，網上遷移由部署專案的 Drizzle 記錄管理。這套服務與外層 hoho-events 無關，不共用其帳戶、設定或後端。
