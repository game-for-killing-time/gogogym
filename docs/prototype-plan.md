# 第一版規格與開發次序

## 第一個可玩版本

目標是驗證每日訓練與社交循環。先做本機單人操作，再加入真正多人連線；模擬角色必須清楚標示，不能當作真人在線。

完整第一版目標包含一間12人房、五類各一款器材、三張每日券、角色五類能力及熟練度、雙人拍檔、一款團體夜跑、一個天台建設目標。三至四人循環站、完整衣櫃、飲品贈送、投票裝修留待核心成立後。

目前已完成五類訓練、六個可用設施（含兩部跑步機）、場景內操作與結算、正式與練習模式及本機存檔；另已接入最多12人同時在線的共享房間、邀請連結、移動、訓練姿勢與表情同步。本機雙瀏覽器及390像素寬手機佈局已驗證，Sites 第1版已發布；公開網站亦已用兩個獨立瀏覽器用戶端驗證加入、移動、划船動作及暫停狀態。雙人拍檔、團體夜跑、固定會員、帳戶成長同步與可進入的天台尚未實作。

## 五類操作原型

| 類別／器材 | 操作與評分 | 長度 |
| --- | --- | --- |
| 推力／臥推 | 按住空白鍵發力，右方綠區放開；回落到左方綠區再按一下接住，分別計算發力與承接時機 | 6次 |
| 拉力／划船機 | 按住空白鍵拉動，綠區放開；依拉動幅度評分，手柄自動回收後開始下一次 | 6次 |
| 腿部／深蹲架 | 按住空白鍵下降，綠區放開；依深度與下降控制評分，角色自動起身 | 6次 |
| 核心／訓練墊 | 按住 A / D 抵消重心漂移，依留在中央綠區的時間評分 | 25秒 |
| 心肺／跑步機 | A / D 跟腳印交替踏步，依方向與節奏時機評分；Shift 衝刺消耗體力，放開回氣 | 25秒 |

觸控按鈕與鍵盤操作相同。所有訓練在器材位置顯示角色動作與浮動操作條；暫停會清除按住狀態，繼續後再輸入。臥推、划船與深蹲的未完成動作有超時處理，避免一節訓練無限停留。

一節結束時須已有至少三次操作記錄，才可結算；核心另需累積至少1.5秒方向修正。核心的鍵盤重複事件、同時按左右及瞬間點按不能充當有效修正。純粹等待訓練結束不扣券也不給獎勵。

六個實體設施各有固定 `stationKey`，但每日額度依五類 `id` 計算；兩部跑步機同屬 `cardio`。點選器材或名稱應前往該實體設施，附近互動應選擇最近的接近位置。啞鈴架等其他家具仍是陳設。

多人 v1 每件器材同時只供一人使用，由伺服器決定誰取得位置，避免不同畫面把同一位置分配給兩人。這是六個現有設施下的原型安排；原構思中熱門器材的並行訓練位置仍為後續目標。

## 本輪具體規則

- 暫以香港時間凌晨04:00為遊戲日分界，星期一04:00為週分界。這是可調整的產品假設。
- 正式完成一節扣一張券。同日同類只能結算一次；練習不限次但不產出資源。
- 完成分數為0至1之間有限數值，成長為100加四捨五入後的20乘分數。
- 每節將成長加入相應能力；該類熟練次數加一。技能等級門檻尚待試玩決定。
- 每日重置只清除當日使用紀錄；每週重置只清除當週參與及建設計數，長期能力保留。
- 每週前12節各貢獻1點工程進度。暫定工程目標為每名活躍會員8點，最低8點；12名活躍會員即96點。週初快照固定。
- 每週四個不同遊戲日完成正式訓練，達成恆常獎勵資格；五類齊全達成全面訓練資格。領獎及獎品系統稍後實作。
- 每次完成有唯一識別碼，重送不重複扣券或派獎。正式連線版本由伺服器核發及驗證識別碼、進度與時間。

## 製作順序與驗收

1. 規則原型：驗證額度、輪換、跨日跨週、收益上限、重複結算和建設貢獻。本輪已建立純邏輯與測試。
2. 單人操作原型：五類完整操作循環、場景內結算及練習模式已接入。25項自動檢查通過，包括入口與六個設施的42條有方向路線。瀏覽器已完成五類操作，驗證每日三類、重複與第四類限制、練習零收益、暫停及重新載入保存；桌面和390 × 844畫面均已檢查。下一輪試玩仍需觀察難度、失誤後的回饋及重玩意願。
3. 日式像素房間：角色走動、器材互動、個人狀態、課表和休息區。鍵盤與觸控均可操作，文字不能因像素風而難讀。
4. 多人連線 v1：房間碼與邀請連結、12人在線上限、移動、五類訓練姿勢、表情、器材使用權及重連已實作。完整45項測試通過，涵蓋第13人拒絕及實際 HTTP 同步；本機雙瀏覽器已驗證移動、划船姿勢、暫停、器材佔用、重新載入與離場，亦完成390像素寬手機檢查。Sites 第1版已發布；公開網站以兩個獨立瀏覽器用戶端完成邀請加入、移動與划船同步驗證，未記錄 JavaScript 錯誤。12人容量由自動測試驗證，12名真人同場試玩仍待進行。固定會員及雙人合作邀請未實作。
5. 帳戶與訓練伺服器化：D1 已保存房間狀態，但能力、每日券及結算仍在瀏覽器。下一階段加入權威時間、訓練流程驗證、一次性結算、未完成課程恢復、帳戶進度與固定會員管理，驗證改動本機時間不能多領券，並行結算不能超支。
6. 團體夜跑及建設：人數縮放、離線成員進度、週初目標快照與獎勵領取。測試中途退出、房主離線及重複領獎。
7. 12人試玩：先收集完成率、重玩意願、社交停留原因，再調整時間及數值。

多人 v1 使用約250毫秒間隔的 HTTP 狀態同步，伺服器以資料庫的單次條件寫入處理容量與器材使用權。本機預覽使用 Node.js 內建 SQLite，網上 Sites 版本使用 D1，兩者共用房間處理程式。房間碼有效24小時；20秒未收到同步的玩家會從在線名單移除並釋放器材。詳細規格見 [multiplayer-v1.md](multiplayer-v1.md)。本專案不借用外層 hoho-events 的帳戶、設定或後端。

## 畫面流程

進入房間 → 查看今日課表 → 選器材 → 選正式或練習 → 操作訓練 → 結算 → 返回房間。

房間常駐顯示剩餘訓練券、今日已練類別及連線人數，課表列出全部五類。器材旁顯示可否正式訓練或是否有人使用；不能正式結算時提供練習。結算浮動面板列出本次增加的能力、熟練度及個人建設點數。房間入口提供暱稱、開房、房間碼、邀請連結、同房名單及離場；角色上方的暱稱與彩色名牌用來辨認其他玩家。

## 尚待試玩的產品選擇

正式名稱、角色比例、房間視角、音樂方向、主要裝置、課程長度、能力等級門檻、週獎勵內容與活躍會員判定。暫定活躍會員為上週有正式訓練者，新房首週以建立週目標時的會員名單計算。
